A small patch: two more things scripts can do, and sturdier builds behind the scenes.

## Download

| | Folio | Folio Lite (no plugins) |
|---|---|---|
| **macOS** (Apple Silicon and Intel) | `Folio-2.0.4-macos-universal.zip` | `Folio-Lite-2.0.4-macos-universal.zip` |
| **Windows** (64-bit) | `Folio-2.0.4-windows-x64.zip` | `Folio-Lite-2.0.4-windows-x64.zip` |
| **Linux** (x86-64) | `folio-2.0.4-linux-x64.tar.gz` | `folio-lite-2.0.4-linux-x64.tar.gz` |

New to Folio? The [user guide](https://github.com/solacecasino/folio#readme) takes about ten minutes to read.

## Lua

- **Readable menu names.** `folio.register_command("date", fn, "Insert Date")` shows "Insert Date" in the Scripts menu. The third argument is optional, so scripts that pass only a name and a function work as before, and the menu shows the name.
- **`folio.get_path()`** returns the document's file path, or `nil` if it hasn't been saved yet. It's only the path: scripts still can't read or write files.
- **`folio.notify(text)`** shows a short message in the status line, as adapters already can.

The `init.lua.example` that Folio puts in the config folder uses all three. A copy you already have stays as it is.

## Behind the scenes

- Every change is now linted and tested on macOS, Windows and Linux as soon as it's pushed, not only on release day. This includes the Folio Lite build, and it has already caught one leftover from 2.0.0 that only Lite compiled.
- When GitHub cancels a build because it ran short of machines, which happened during 2.0.3, the build now retries by itself, up to twice. Real failures aren't retried.
- The build tools are updated to their current versions. The Windows build no longer installs an OpenGL stand-in, which Folio stopped needing in 2.0.0.

## Compatibility

Nothing existing changed. The Lua functions from 2.0.1–2.0.3 work exactly as before. Documents, themes, settings, `keys.toml`, adapters and plugins are untouched.
