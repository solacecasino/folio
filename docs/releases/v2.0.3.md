A small patch: Lua commands now have their own menu, and a compatibility fix for Linux.

## Download

| | Folio | Folio Lite (no plugins) |
|---|---|---|
| **macOS** (Apple Silicon and Intel) | `Folio-2.0.3-macos-universal.zip` | `Folio-Lite-2.0.3-macos-universal.zip` |
| **Windows** (64-bit) | `Folio-2.0.3-windows-x64.zip` | `Folio-Lite-2.0.3-windows-x64.zip` |
| **Linux** (x86-64) | `folio-2.0.3-linux-x64.tar.gz` | `folio-lite-2.0.3-linux-x64.tar.gz` |

New to Folio? The [user guide](https://github.com/solacecasino/folio#readme) takes about ten minutes to read.

## What changed

- **Linux: the window is called `Folio` again.** 2.0.0 renamed it to lowercase `folio`. That could break window-manager rules, `xdotool` scripts or anything else that matched Folio's window by name. It's back to what Folio 1.x used.
- **A Scripts menu.** Commands that your `init.lua` registers now appear in their own menu, so you can run them without binding a key. If you bound a key in `keys.toml`, the menu shows it.
- **`Cmd+/` shows Lua commands that don't have a key yet**, alongside every other shortcut.
- **An example script.** Folio now puts `init.lua.example` in its config folder, with two working commands: insert the date, and wrap the selection in quotes. Rename it to `init.lua` and they appear right away. Folio doesn't create `init.lua` itself, so Lua still never starts unless you opt in.
- **The guide now covers reporting problems in more detail.** It explains what Copy Debug Info includes, now with memory and window size, and how `FOLIO_FRAME_TIMES=1` helps when Folio feels slow.

## Compatibility

Nothing existing changed. The only new file in the config folder is `init.lua.example`, and nothing reads it. Documents, themes, settings, `keys.toml`, adapters, plugins and Lua scripts work as in 2.0.2.
